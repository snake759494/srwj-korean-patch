# v2.4 — 줄바꿈을 '끊는 자리'부터 다시 잡았습니다

[이슈 #1](https://github.com/snake759494/srwj-korean-patch/issues/1)(10화) 46건 중 38건이 **줄맞춤**이었습니다. 개별 오타가 아니라 줄바꿈 규칙 자체의 문제라, 대사창을 실측하고 규칙을 고쳤습니다.

## 무엇이 문제였나

대사는 **띄어쓰기 기준으로 앞 줄부터 꽉 채우는 방식(그리디)** 으로 나눴습니다. 그래서 구(句)가 두 줄로 갈리고, 한 글자만 덩그러니 남는 일이 잦았습니다.

```
전   노획할 수 있게 됐어 그 / 분이 뭐 때문에 자기      ← '그' 만 남기고 끊김
후   노획할 수 있게 됐어 / 그 분이 뭐 때문에

전   꿈? 무슨 / 소리야?                              ← '무슨 소리야?' 가 갈림
후   꿈? / 무슨 소리야?
```

## 어떻게 고쳤나

줄 수는 그대로 두고 **끊는 자리만 다시 고릅니다.** 같은 폭 안에서 남는 칸의 제곱합이 가장 작은 조합을 고르되,

- 한 글자만 남기고 끊으면 벌점
- 문장부호(`.` `!` `?` `…`) 뒤에서 끊으면 가점
- 첫 줄은 화자명이 앞에 붙어 짧아 보이므로 채우는 쪽에 가중치

시나리오는 [`0.시나리오/srwj_wrap.py`](../0.시나리오/srwj_wrap.py)의 `balanced_wrap`, 전투는 [`2. 전투대사패치/rewrap_balance.py`](../2.%20전투대사패치/rewrap_balance.py)가 담당합니다.

| | 결과 |
|---|---|
| 시나리오 줄바꿈이 바뀐 턴 | 15,928 / 35,268 (45%) |
| 한 글자로 끝나는 줄 | 9,188 → 1,570 (**−83%**) |
| 시나리오 총 줄 수 | 115,598 → 115,598 (변화 없음) |
| 전투 대사 줄바꿈이 바뀐 항목 | 4,900 / 11,271 |
| 전투 대사 총 줄 수 | 23,675 → **22,528** (줄어듦) |

전투 대사는 2줄→1줄 557건, 3줄→2줄 715건으로 오히려 짧아졌습니다. 번역가가 손으로 넣은 줄바꿈을 그대로 쓰던 것을 폭에 맞춰 다시 채웠기 때문입니다.

## 전투 대사 첫 줄 예산을 10칸 → 8칸으로

v2.3에서 첫 줄에 `이름「` 자리를 예약하도록 고쳤는데, 그때 잡은 10칸은 **화자명이 6자 이상이면 창을 넘길 수 있었습니다.** 이번에 스크린샷으로 대사창을 실측했습니다.

| | 실측값 |
|---|---|
| 글자 한 칸 | 약 12 px |
| 첫 줄이 쓸 수 있는 폭 | 약 180 px = **15칸** (첫 줄은 이어지는 줄보다 2칸 왼쪽에서 시작) |
| 이어지는 줄 | 약 172 px = 14칸 |

화자명은 최대 6~7자이므로 `이름(7) + 「(1) + 본문(8) = 16칸`이 한계선입니다. 첫 줄 예산을 8칸으로 낮춰 여유를 뒀습니다.

같은 이유로 **시나리오 첫 줄 7칸은 그대로 뒀습니다.** 넓히면 이름이 긴 화자에서 첫 줄이 통째로 사라질 수 있습니다([v2.3](RELEASE_NOTES_v2.3.1.md)에서 고친 바로 그 증상입니다).

## 고치지 못한 것

첫 줄이 짧아 보이는 항목 일부(`... / 그러게말이야`, `흐음... / 그래?`, `아무것도 / 아니야`)는 **화자명이 첫 줄 앞에 함께 그려지기 때문**입니다. 본문이 8칸을 넘으면 두 줄이 될 수밖에 없고, 무리해서 넓히면 이름이 긴 화자에서 첫 줄 전체가 사라집니다. 본문을 줄이는 방법뿐이라 이번에는 두지 않았습니다.
